# DTC Site Search Skill Logic

## Goal

Hermes is being specialized for TikTok SKU to independent-site product search.
The agent receives a TikTok `sku_id` and a DTC site URL, explores whether the
site has likely candidate products using TikTok title, description, and images,
and records the exploration without deciding the final same-item match.

## Runtime Flow

1. Load TikTok SKU evidence with `tiktok_sku_lookup`.
2. Load learned site guidance with `dtc_site_search_context(site_url)`.
3. Use `browser_navigate` to go directly to the user-provided DTC URL, then
   `browser_snapshot` and interactive browser tools such as `browser_click`,
   `browser_type`, and `browser_press`. Do not start with Google or broad web
   search.
4. Browse/search the independent site using search boxes, navigation,
   collection pages, product pages, and image/title/description evidence. Use
   web search only after direct navigation/on-site exploration fails or reveals
   a related catalog domain.
5. After one complete exploration of one site for one SKU, call
   `dtc_site_search_record`.
6. The recorder stores the raw structured exploration under
   `./dtc_site_search_data/<site-key>/raw/` and starts a background
   cleanup thread.
7. The background cleanup LLM writes a cleaned chain under
   `./dtc_site_search_data/<site-key>/cleaned/`.
8. After every configured N successful cleaned chains for the same normalized
   site URL, a background skill update job creates or rewrites
   `./skills/dtc-site-search/dtc-site-*/SKILL.md`.
9. Refresh the DTC site-search index skill at
   `./skills/dtc-site-search-index/SKILL.md`.

`raw/` stores the structured record from one `dtc_site_search_record` call. It
does not contain the original Hermes transcript and is not produced by scanning
all explorations. `cleaned/` is generated by a background LLM cleanup pass for
that same single raw record, using Hermes' built-in session database as the
primary source when `session_id` is available and using `raw/` as structured
metadata/summary. The original conversation remains only in Hermes'
built-in session database.

When the user asks for same-item judgment, the agent should use visual
comparison when both TikTok SKU images and independent-site candidate images
are available. If either side has no images, skip visual comparison and rely on
the available text/product evidence.

The generated skill should summarize reusable website-search strategy only:
whether to use the site's search box, navigation, all-products pages,
collection pages, a related catalog domain, or full enumeration for tiny
catalogs. It must not copy concrete SKU examples, one-off search queries, or
candidate product details into the skill.

N is configured at `dtc_site_search.success_threshold` in `config.yaml`, with
default `5`. For test or one-off runtime overrides, set
`HERMES_DTC_SITE_SEARCH_SUCCESS_THRESHOLD`.

Default storage is repo-local:

- exploration data: `dtc_site_search_data/`
- generated site skills: `skills/dtc-site-search/`
- generated site skill index: `skills/dtc-site-search-index/SKILL.md`

Override with `HERMES_DTC_SITE_SEARCH_DATA_DIR` and
`HERMES_DTC_SITE_SEARCH_SKILL_DIR` if needed.

## Skill Policy Change

Generic single-conversation skill generation has been disabled. The normal
conversation prompt no longer asks the foreground agent to create or patch
skills, and `skill_manage` refuses foreground mutation unless explicitly
overridden with `HERMES_ALLOW_FOREGROUND_SKILL_MANAGE=1`.

The existing background self-improvement review may still save memory, but its
skill branch now exits with `Nothing to save.` DTC site skills are generated
only from cleaned exploration chains, not raw transcripts.
